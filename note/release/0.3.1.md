# 0.3.1

性能优化版本。红线：安全性/稳定性/兼容性零让步——工具面（137）零变化，护栏行为不变，分发行为经黄金快照 138/138 逐字节校验。基准程序首次入库（`benchmark/`，5 项），对比报告见 `note/report/perf/2026-09-26-perf-optimization-0.3.1.md`。

## 变更

- `tools/list` 工具表进程内缓存：每次枚举 411.7 µs → 0.1 µs（4117x），序列化输出字节级一致。
- `call_tool` 分发链（135 分支 if/elif，圈复杂度 ~136）→ 137 项路由表：性能中性（如实记录：分发本就是 µs 级非瓶颈），架构收口分析报告"发现 3"，逐分支可测。
- 基准与回归设施：`bench_list_tools` / `bench_dispatch` / `bench_hotpath` / `bench_subprocess` / `bench_rest` + `verify_dispatch_equivalence` 黄金快照回归门（可作未来重构的等价性校验）。
- 新增 2 项行为锁测试（单测 45 → 47）。

## 实测数据

- 子进程并发（真实 vmrun ×16，上限 8）：串行 5184 ms → 1023 ms（**5.1x**），16/16 无串扰。
- REST 连接复用（50 请求）：TCP 连接 50 → 1，墙钟 607 ms → 55 ms（**11.0x**）。
- 服务端 Python 侧单次调用总开销：中位 9.8 µs（P95 11.2 µs），相对百 ms 级 I/O 等待可忽略。

## 评估后否决（基准说话，未进入代码）

- `_vmx_encryption` 整读+正则定位：0.85-0.98x（更慢，I/O 主导）。
- `decode_output` ASCII 快速路径：0.55-1.0x（更慢，utf-8 对 ASCII 已近 memcpy）。
- `redact_secrets` 正则化：级联替换边界语义风险 > 零收益。
