# 0.3.0

依据 2026-09-26 本机实战经验（0.2.0 之后的调用复盘）与 AI/LLM Agent × VMware 生态调研（`note/research/2026-09-26-ai-agent-vmware-automation-survey.md`，护栏设计参照 TheEvalon/vmware-vcenter-mcp 与 github/github-mcp-server 的三层模式）。工具数不变（137），工具面零破坏。

## 轮1：安全护栏三层

- `VMWARE_READ_ONLY=1` 全局只读开关：置位后 24 个破坏性工具（删除/断电/还原快照/rm 等）直接拒绝并返回 `read_only: true`，查询类不受影响。
- confirm/dry-run 二次确认：破坏性工具未带 `confirm: true` 时返回 dry-run 预览（含将执行的参数、`ok:false`、`dry_run:true`），不产生副作用；确认后重调才执行。
- annotations 注入：只读工具标 `readOnlyHint: true`，破坏性工具标 `readOnlyHint: false` + `destructiveHint: true`；`vm_power_set` 仅 `state:"off"` 视为破坏性（运行期按值判定）。
- 兼容性说明：`confirm` 是新增可选参数；不传时行为从"直接执行"变为 dry-run——这是护栏语义的有意修正，已有自动流如需保持旧直执行行为，请携带 `confirm: true`。

## 轮2：性能

- REST 连接复用：httpx.AsyncClient 改进程级共享池（原先每请求新建连接），vmrest 高频轮询不再反复握手。
- 子进程并发上限：vmrun/vmcli 共用 `VMWARE_MAX_CONCURRENCY`（默认 8）信号量，防并发唤醒风暴拖垮宿主。
- 输出截断：单次返回超 `VMWARE_MAX_OUTPUT`（默认 20000 字符）自动截断并附原长提示，`0` 关闭；防单次大输出挤爆模型上下文。

## 轮3：代码卫生

- 删除 6 个零引用死方法（vmrun 4 + vmcli 2，grep 验证仅 def 行命中）。
- 密码脱敏：失败路径的错误输出与日志中 guest 密码、加密密码统一替换为 `***`。注意：argv 明文传递是 vmrun/vmcli 的机制（进程列表可见），无法在 MCP 层根治，敏感环境请评估。
- `VMWARE_TLS_VERIFY`：REST 连接 TLS 校验默认关闭（vmrest 为 localhost http，保持原行为），可显式开启。

## 轮4：可观测性

- 每次工具调用向 stderr 记一行 `tool=<名> ok=<真> duration_ms=<毫秒>`（失败附 http_status/异常类型）；`VMWARE_LOG_LEVEL` 控制（默认 WARNING 静默，INFO 开启）。stdout 仅承载 MCP 协议，零污染。

## 测试与验证

- 单元测试 29 → **45**（护栏/连接池/截断/信号量/脱敏/日志），全绿。
- 集成测试（`VMWARE_IT=1`，只读类）在本机 VMware Workstation 实测通过；写操作按约定未执行。

## 明确不做

- 三家族工具合并、v1 SDK 升 v2（用户既有 v1 项目，v1 线仍在维护期，无硬需求不迁）。
- vmcli/REST 通道加密支持承诺（仍无实测依据，加密 VM 限 `vmrun_*` 族）。
