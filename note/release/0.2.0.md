# 0.2.0

依据 2026-09-25 三份使用复盘（`00-多会话经验汇总与开发准备.md`、`vmware-mcp调用体验与开发建议.md`、`VMware自动化实战经验总结.md`）的 P0/P1/P2 清单落地。工具 130 → **137**。

## P0：进程卫生 / 加密密码 / 结构化错误

- vmrun/vmcli 子进程 stdin 接 `DEVNULL`：vmrun 等密码时立即报错退出，不再继承 MCP 服务端 stdio 管道挂死（此前 344 次调用中 51 次失败均为 30s 超时墙的直接根因）。
- 分级超时并杀进程：查询 30s / 电源 90s / 长任务 600s（`VMWARE_TIMEOUT_QUERY/POWER/LONG` 可覆盖），超时后 vmrun 进程被终止，杜绝僵尸进程延迟产生电源副作用。
- 加密密码三入口（优先级从高到低）：工具参数 `enc_pass`（全部带 `vm_id` 的 `vmrun_*` 工具）→ `set_vm_encryption_password` 预存 → env `VMWARE_ENC_PASSWORD`。底层以 `vmrun -vp` 传递；ContextVar 按调用隔离，并发安全。
- 失败统一返回结构化 JSON：`{ok, tool, error, exit_code, stdout, stderr, duration_ms, timeout, hint}`；`hint` 覆盖要加密密码/密码错误/guest 空密码/Tools 未装/路径不存在五类常见错误。未预期异常不再静默，未知工具不再返回误导性 "OK"。
- `get_vmx_path` 查不到 vm_id 改为报错（原静默空串导致后续工具返回误导性 OK）。

## P1：诊断工具 / 传输 / 修复

- 新增 `vm_resolve`（模糊名 → vmx + 电源 + 加密类型）、`vm_health`（电源/Tools/IP/加密/.vmem+.vmss 空闲挂起判据/log 尾 20 行一次拿全）、`vm_log_tail`。
- 新增 `vmrun_copy_dir_to/from` 目录树递归传输（include/exclude 后缀过滤）。真实负载 52% 集中在文件搬运，此为该主路的第一块拼图。`copy_dir_from` 依赖 vmrun ls 输出容错解析，解析失败行计入 `skipped`（vmrun ls 布局未在全部 guest OS 验证）。
- `vmrun_run`/`vmrun_script` 的 `args` 支持**字符串数组**；字符串不再按空格 `split`（含空格 Windows 路径不再被拆碎）。**破坏性变更**：依赖自动拆分的调用需改为数组。
- 子进程输出解码 utf-8 失败退 gb18030（中文 Windows 控制台输出不再乱码）。
- `_vm_path_cache` 加锁、命中但 vmx 文件已不存在时失效重建；三适配器改进程级单例。

## P1：工具描述重写

- 136 个工具描述统一模板：通道｜动作｜前提（vmrest/Tools/凭据）｜副作用（soft/hard/不可逆）；三家族重叠工具显式分工与互指；全部 `vm_id` 参数注入双语义 schema 说明（vmx 绝对路径或 REST vm_id）。

## P2

- `screenshot_ocr`：截屏 + RapidOCR 文本化，可选依赖 `pip install 'vmware-mcp[ocr]'`；未安装或坏图（如锁屏全黑）返回结构化提示。
- pyproject 增 `ocr`/`dev` extras 与 pytest `integration` marker。

## 明确不做

- 三家族工具合并去重（破坏性大，仅做描述分工）。
- vmrest/vmcli 通道的加密 VM 支持（无实测依据，README 已注明加密 VM 走 vmrun 系）。

## 验证

- 单元测试 22 项通过（`pytest`）；集成测试 3 项需真实 VMware（`VMWARE_IT=1 pytest -m integration`）。
- 工具数 137 = REST 19 + vmrun 48 + vmcli 65 + server 5（脚本实测）；分支与 list_tools 一一对应校验通过。
