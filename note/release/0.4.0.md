# 0.4.0 工作流组合工具

依据 647 次真实会话调用记录的量化分析：单次调用延迟已非瓶颈，摩擦在「往返圈数」——68 个「上传→执行→回拷」三连圈、106/124 次执行输出 ≤50B（stdout 通道闲置）、copy_from 以 140 次居首。本版把高频多连调用合并为单次调用，直接省模型回合（每回合实测重读 ~169k token 上下文）。

## 新增

- `vmrun_run_job`：上传脚本文本→执行→回传 stdout+exit_code 并自动清理 guest 临时文件。copy_to+run+copy_from 三连（3 次调用/3 回合）→ 1 次调用/1 回合。支持 bash/sh/cmd；`no_wait` 启动后台作业配合收集链。
- `vmrun_read_file`：直读 guest 文本文件内容到对话（copy_from+本地 Read → 1 次调用）；二进制拒绝、超限截断标记。
- `vmrun_wait_file`：轮询等待 guest 文件出现（收 no_wait 作业产物）；凭据/Tools 类错误首探即抛。
- 新 env：`VMWARE_HOST_TEMP_DIR`、`VMWARE_READ_FILE_KB`（均可选）。

## 描述修正（引导直达正确工具）

- `vmrun_run`/`vmrun_script` 明示「不捕获程序 stdout」（VIX 机制本身）；需要输出改用 run_job。
- `vmrun_script` 明示 `script` 是 guest 内文件路径而非脚本文本。
- `vmrun_copy_dir_to/from` 加「多于 3 个文件优先用我」触发条件（此前 0 次调用）。

## 真机验证（RHEL-10）抓出并修复的缺陷

- POSIX `{ }` 块挡不住用户脚本 `exit` → 改子 shell `( )` 包裹，`rc=$?` 走标记通道；cmd 用 `call :__vmjob` 例程隔离。
- 输出文件启动即创建导致的「半成品窗口」→ `.part` 中转 + `mv`/`move` 原子发布，`wait_file` 见最终名即作业完成。
- VIX 对 guest 符号链接报 OK 却不落宿主文件 → `read_file` 结构化报错并指引 `run_job cat` 方案。

## 量化与回归

- 真机中位：run_job 5.49s（含并发清理）/legacy 三连 4.42s，回合 3→1；read_file 0.87–1.01s；错凭据 fail-fast 2.30s（对照 15s）。以最重历史会话（68 圈）测算可省 ~136 个模型回合、20–50 分钟墙钟。
- 单元测试 64/64；黄金快照 141/141 逐字节一致；旧工具语义零改动。
