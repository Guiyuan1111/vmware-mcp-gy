# 0.4.1 工具面作用域（VMWARE_TOOLS）

对照 mcp-server-builder skill 的规模指引（「工具数量增长导致 description 膨胀时按领域拆分」）落地：单一服务器内按家族裁剪工具暴露面，无需拆分成多个服务器或改动宿主注册。

## 新增

- env `VMWARE_TOOLS`：`rest` / `vmrun` / `vmcli` / `core`（逗号组合）；`all` 或缺省 = 全量 140（行为与 0.4.0 完全一致）。
- 家族映射取自路由表适配器标记：vmrun 53 / vmcli 65 / rest 19 / core 3。`vm_resolve`、`vm_health`、`vm_log_tail` 为 core（诊断与 vm_id 解析入口），任何作用域下保留。
- 作用域外的工具调用在入口即被结构化拒绝（先于护栏与 vm_id 解析）；非法值回退全量并 stderr 告警（可用性优先）。

## 收益

- 典型 guest 操作工作流 `VMWARE_TOOLS=vmrun`：56 工具 / 35.7KB 工具列表（全量 140 / 74.8KB 的 48%），模型选工具噪声减半；REST 域 22 工具 / 14%。
- 作用域同时是暴露面收缩手段（如只读宿主场景 `VMWARE_TOOLS=rest,core`）。

## 工程质量（对照 skill 检查项）

- stdout 协议通道零污染：新增 `benchmark/protocol_conformance.py`（9 项 stdio JSON-RPC 全程会话断言，无需 VMware）：握手、全量列表、未知工具结构化错误、dry-run 护栏经协议层在线、错误路径后服务器存活、作用域裁剪与域外守卫、stdout 全程 JSON 纯净。
- 回归：单元测试 70/70；黄金快照 141/141 逐字节一致；默认行为零变化。
