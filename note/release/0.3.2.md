# 0.3.2

性能优化第二期（承接 0.3.1，见对比报告 `note/report/perf/2026-09-26-perf-optimization-0.3.2.md`）。红线同前：工具面（137）零变化，护栏行为不变，黄金快照 138/138 逐字节全绿。

## 变更

- **vm_health / vm_resolve 内部并发化**：3 个互不依赖的只读探测（及多匹配电源查询）由串行改 gather 并发。真实 vmrun 实测 vm_health 1021 ms → 421 ms（**2.4x**）；结果逐字段一致（错误分支语义经专项单测对照旧串行参照锁定）、调用序列不变、并发仍受 `VMWARE_MAX_CONCURRENCY` 全局限流。
- **`VMWARE_COMPACT_OUTPUT=1`（可选）**：成功路径 JSON 紧凑序列化，典型负载省 **25%** 字符（token 近似同比例）；默认关闭时输出与 0.3.1 逐字节一致；失败路径不受影响。
- 基准新增 `bench_composite.py` / `bench_output.py`；单测 47 → **52**。

## 评估后不做（详见报告 §评估后不做）

- REST 优先替代重叠 vmrun 操作（上限 ~10x）：需 vmrest 凭据，本机未配置，按"无实测依据不上线"纪律暂缓，待凭据策略确定后实施。
- Tool Search / deferred loading：宿主侧功能，无服务端实现点。

## 明确不做（延续 0.3.1）

- listChanged 通知（工具集静态）、orjson / to_thread（µs 级收益不值复杂度）、聚合批处理工具。
