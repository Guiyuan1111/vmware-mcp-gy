# 0.4.2 通道剖析与生命周期剖析（性能线收口）

延续「先测量、数据定案、收益不足即否决并记录」的方法论，本轮对两个此前未测量过的维度做剖析。

## 变更

- `vm_health` REST 快路径：REST vm_id 形态下 `running` 探测走 `get_power_state`（纯元数据，关机 VM 也可用），poweredOn→true 等价映射；REST 不可达/401 自动回退 vmrun；vmx 直通形态行为不变。价值：`VMWARE_TOOLS=rest` 场景 running 仍可诊断 + 关机/运行态通道收益 1.21x（N=5 中位 956→789ms）。
- 新增 `benchmark/bench_health_channels.py`：新旧通道同 VM 天然对照 + 401 模拟回退验证。
- 新增 `benchmark/bench_lifecycle.py`：进程生命周期剖析（import 分解/协议就绪/工具表构建/序列化耗时）。

## 测量否决记录（防止重复尝试）

- **vm_health 的 ip REST 化**：vmrest `/ip` 底层同为 VIX 且对关机 VM 返回 409，新旧打平（1.04x）——已收缩掉。
- **httpx 懒加载**：mcp 加载后边际 import 为噪声级（共享 anyio/h11），否决。
- **作用域过滤结果缓存**：140 项 ~5µs/会话一次，零收益，不做。

## 生命周期结论

冷启动 ~900ms 中 mcp SDK import 占 ~756ms（硬依赖），自有代码与工具表构建（0.6ms）均为毫秒级——冷启动无可优化空间，属每会话一次性成本。

## 口径更正

0.4.1 报告的 74.8KB 为紧凑 JSON 口径；SDK 实发 indent=2 形态为 104.5KB。作用域相对节省比例结论不变。
