# vmware-mcp-gy 修复方案（依据三份经验文档，P0→P1→P2 三批）

依据：`00-多会话经验汇总与开发准备.md`、`vmware-mcp调用体验与开发建议.md`、`VMware自动化实战经验总结.md`。P0 全部问题已在底座代码逐条坐实（server.py/vmrun.py/vmcli.py/client.py 本轮重读核对）。全程细粒度 git commit、不写 co-author。

## 第一批 P0（对应文档二"如果只改三件事"）

### 1. 进程卫生：stdin 隔离 + 分级超时 + 超时杀进程
文件：`src/vmware_mcp/vmrun.py`、`vmcli.py`（两处 `_run` 同构，改法相同）
- `create_subprocess_exec(..., stdin=asyncio.subprocess.DEVNULL)`——vmrun 等密码时立即报错退出而非挂死共享的 stdio 管道
- `asyncio.wait_for(proc.communicate(), timeout=...)`；超时则 `proc.kill(); await proc.wait()`，抛超时 ToolError，杜绝僵尸 vmrun
- 超时分档：默认 30s；电源类（start/stop/reset/suspend/pause/unpause 及 vmcli Power::*）90s；长任务（clone/upgradevm/template Deploy/Create/disk Extend 等）600s；env `VMWARE_TIMEOUT_QUERY`/`VMWARE_TIMEOUT_POWER`/`VMWARE_TIMEOUT_LONG` 可覆盖
- 实现上用模块级"命令名→档位"dict，`_run` 按命令查档，不逐个改 113 个方法签名

### 2. 加密密码入口（env + 工具参数 + set 工具，三选一全做）
- server 级 `_enc_passwords: dict[vmx路径, 密码]`
- 新工具 `set_vm_encryption_password(vm_id, password)`（文档二 P0-1c）
- env `VMWARE_ENC_PASSWORD` 兜底（沿用现有 VMWARE_USERNAME/PASSWORD 命名风格）
- 工具级参数：list_tools 末尾对全部非 REST 工具循环追加可选 prop `enc_pass`（不改 130 条 T() 调用）；call_tool 开头统一解析 `enc = a.pop("enc_pass","") or _enc_passwords.get(缓存 vmx) or env`，赋给 `vmrun.enc_pass`/`vmcli.enc_pass`——一处代码对全部 111 个 vmrun/vmcli 分支生效
- `vmrun._run` 组装：`[vmrun, "-T", "ws"] + (["-vp", enc] if enc else []) + 原有参数`
- vmcli 的加密支持未验证（无实测依据），本期仅透传不承诺；REST/vmrest 无已知加密参数（未验证）——README 明确"加密 VM 请用 vmrun_* 族"（与文档三结论一致）

### 3. 结构化错误 + hint 快速失败
- 新文件 `src/vmware_mcp/errors.py`：`ToolError(Exception)`，字段 ok/tool/exit_code/stdout/stderr/duration_ms/hint/timeout
- vmrun/vmcli 失败路径改抛 ToolError（带 exit_code 与解码后输出）
- call_tool 整体 try/except：ToolError → 返回结构化 JSON；httpx.HTTPStatusError → `{ok:false,status,body,hint}`；其余异常 → `{ok:false,error,hint:""}`
- hint 映射表（错误文本子串→一句话下一步）："password is required"→"VM 已加密：提供 enc_pass 或设 VMWARE_ENC_PASSWORD"；"Incorrect password"→密码错误；"does not support empty passwords"→"guest 空密码被 VIX 硬拒绝，请为账户设密码"；Tools 相关→"先 tools_install"；Invalid VMX/cannot find→路径检查
- `get_vmx_path` 查不到不再静默空串：抛 ToolError(hint="先调用 vm_list 或 vm_resolve")
- 成功路径返回格式保持现状（不破坏现有可用流）——对文档"错误/成功统一 JSON"的有意裁剪：只统一失败侧
- 验收（文档二 §六）：加密无密码 ≤5s 结构化错误；错误密码返回 Incorrect password；guest 空密码返回 VIX 原文+建议

## 第二批 P1

### 4. 新工具 `vm_resolve(query)`：模糊名/路径片段 → vmx 绝对路径 + power state + vmx 的 encryptionType + Tools 状态（vm_id 歧义的官方解法，文档二 P1-1）
### 5. 新工具 `vm_health(vm_id)`：power + Tools + IP（尽力）+ encryptionType + .vmem/.vmss 存在性（idle 挂起判据，文档三 §四）+ vmware.log 尾 20 行（文档二 P2-1 / 文档一 六.4）
### 6. 新工具 `vm_log_tail(vm_id, lines=50)`：读 {vmx 目录}/vmware.log 尾部
### 7. `copy_dir_to` / `copy_dir_from`：os.walk + 循环复用单文件方法，逐文件进度行，支持简单 include/exclude（52% 真实负载是文件搬运，文档一 §三/§五）
### 8. `run_program`/`run_script` 参数修复（vmrun.py:138）：schema `args` 改 array[string]（breaking，README 与 release 注明），wrapper 停止 split 直接列表传参；兼容 string 时作单个 argv 元素透传
### 9. 编码修复：输出解码先 `locale.getpreferredencoding(False)`，fallback utf-8，errors="replace"
### 10. 缓存与并发卫生：cache 命中但 vmx 文件不存在→重建；asyncio.Lock 保护；call_tool 按分支族惰性创建三实例；README 注明"多 vmrun 并行操作同一 VM 行为未定义"
### 11. 全量 130 条工具描述重写：补 vm_id 语义、前提（需 Tools/vmrest/vmrun）、副作用（soft/hard）、三家族"何时用我"（REST=元数据/网络，vmrun=guest 主力，vmcli=快照/硬件扩展）

## 明确不做 / 风险声明
- 三家族工具合并去重：破坏性大，仅做描述分工（文档一自己也排 P2）
- `verify=False` 不动：vmrest 为 http://localhost，无 TLS 路径，该参数不生效
- vmcli/REST 加密支持：无实测依据，不承诺，README 标注限 vmrun 族
- 三份经验文档本身的过时数字（117 等）不在本方案修改范围（本轮禁止修改文件）；方案只改 vmware-mcp-gy 仓库
